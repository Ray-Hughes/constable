# Assets

Generated by `build_logo.py`, which is checked in so the artwork is reproducible
rather than a one-off export somebody has to redo by hand:

```console
$ python3 docs/assets/build_logo.py "NOTHING SLIPS THROUGH"
```

| File | What it is |
|---|---|
| `logo.png` | Mark, wordmark and tagline. The README header on a light theme. |
| `logo-dark.png` | The same, with the charcoal lifted to a light grey. |
| `logo-square.png` | The mark alone on a square canvas — favicon, avatar, social card. |
| `logo-square-dark.png` | The square mark for dark backgrounds. |

Two colours carry the whole thing: crimson `#9A1331` and charcoal `#363636`. The dark
variants swap the charcoal for `#D6DDE2` and leave the crimson alone, which reads
correctly on both themes without inventing a second palette.

The source artwork is a JPEG on white. `build_logo.py` recovers an alpha channel from
it rather than keying out a flat colour: each pixel is classified by hue and its
coverage read off the green channel, so edges keep their antialiasing and the fills
come back exactly on-brand. Anything under 4% coverage is treated as JPEG ringing and
dropped, which is what stops a faint grey haze appearing over a dark README.

The README uses `<picture>` with `prefers-color-scheme`, so GitHub serves the right
one automatically.
